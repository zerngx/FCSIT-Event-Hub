# Data Dictionary (Sample) — FCSIT Event Hub System

This is a sample of the data dictionary for the proposed system. It describes the data stores and selected data flows from the Level-0 DFD (`diagrams/dfd-level0.drawio`), and selected data elements from the ERD (`diagrams/erd.drawio`).

Notation for composition: `=` is composed of, `+` and, `{ }` repeated, `( )` optional, `[ a | b ]` one of.

## 1. Data stores

| ID | Name | Description | Composition | Read by | Written by |
|---|---|---|---|---|---|
| D1 | Users | Accounts of students, organisers and administrators, and the organiser approval status | user_id + full_name + email + matric_no + programme + year_of_study + phone + photo_url + role + organiser_status + (approved_by) + created_at | 3.0 | 1.0 |
| D2 | Events | Published FCSIT events, their registration rules and screening criteria | event_id + organiser_id + title + description + venue + start_at + end_at + capacity + mode + reg_open_at + reg_close_at + cancel_deadline + checkin_open_at + checkin_close_at + status + {screening criterion} | 2.0, 3.0, 4.0, 6.0 | 2.0 |
| D3 | Registrations | One record per student per event, including waitlist position | registration_id + event_id + student_id + registration_status + (waitlist_position) + registered_at + (cancelled_at) | 5.0, 6.0, 7.0 | 3.0, 4.0, 6.0 |
| D4 | Applications | Resumes submitted for application-based events and their screening results | application_id + registration_id + resume_url + resume_text + (screening_outcome) + {matched_criterion} + {missing_criterion} + (decided_at) | 4.0 | 3.0, 4.0 |
| D5 | Tickets | Personal tickets issued to confirmed participants; the secret generates the rotating QR | ticket_id + registration_id + secret + ticket_status + issued_at | 5.0 | 5.0 |
| D6 | Attendance | Verified check-ins at the venue | attendance_id + ticket_id + scanned_by + checked_in_at | 7.0 | 5.0 |

## 2. Data flows (sample)

| Data flow | From → To | Description | Composition |
|---|---|---|---|
| Registration / application with resume | Student → 3.0 | A student's request to join an event; resume only for application events | event_id + student_id + (resume file) |
| Ranked applicants with reasons | 4.0 → Organiser | Applicants sorted by screening outcome, with the evidence for each criterion | {registration_id + full_name + screening_outcome + {matched_criterion} + {missing_criterion}} |
| Rotating QR ticket | 5.0 → Student | QR code shown on the student's phone; refreshes every 30 seconds | ticket_id + time_step + signature |
| Scanned QR token | Organiser → 5.0 | Content read by the organiser's scanner at the door | ticket_id + time_step + signature + scanned_by |
| Check-in result and identity | 5.0 → Organiser | Accept or reject decision shown on the scanner, with the identity to compare | check_in_result + (rejection_reason) + (full_name + matric_no + photo_url) |
| Attendance report (CSV) | 7.0 → Organiser | Reconciled participant list for one event | event_id + {full_name + matric_no + registration_status + attendance_flag + (checked_in_at)} |

## 3. Data elements (sample)

| Element | Type | Length / format | Validation rule | Description |
|---|---|---|---|---|
| user_id | UUID | 36 characters | System-generated, unique | Identifies a user account |
| matric_no | Text | 8–12 characters, e.g. `25006739` | Required for students; unique | University matric number |
| email | Text | Up to 120 characters | Valid email format; unique | Sign-in and notification address |
| role | Enum | — | `student`, `organiser`, `admin` | Determines access rights |
| organiser_status | Enum | — | `none`, `pending`, `approved`, `rejected` | Progress of an organiser account request |
| capacity | Integer | 1–9999 | Must be greater than 0 | Maximum confirmed participants |
| mode | Enum | — | `open`, `application` | Open: one-click registration. Application: resume and screening |
| registration_status | Enum | — | `registered`, `pending`, `accepted`, `waitlisted`, `rejected`, `cancelled` | Current state of a registration |
| waitlist_position | Integer | 1–9999 | Only set when status is `waitlisted` | Order for automatic promotion |
| screening_outcome | Enum | — | `eligible`, `needs_review`, `not_eligible` | Result of the rule-based resume check. Never an automatic rejection |
| secret | Text | 64 hexadecimal characters | System-generated, never shown to users | Key used to sign the rotating QR token |
| time_step | Integer | Unix time ÷ 30 | Accepted only if within ±1 step of server time | 30-second window in which a QR code is valid |
| signature | Text | 16 characters | Must match HMAC(secret, ticket_id + time_step) | Proves the QR code was generated by the ticket holder's app |
| checked_in_at | Timestamp | ISO 8601, Malaysia time (UTC+8) | Must fall within the event's check-in window | Time the ticket was accepted at the door |
